# Master prompt — Social Discovery App

Start by explaining that this is a fictional-data Flutter browser development preview, not a production dating/payment platform. Ask for the product brief, adult audience, brand guidelines, supported platforms, discovery preferences, invitation/chat rules, moderation requirements and demo versus production goals.

Run the locked dependency install and existing tests before editing. Preserve recipient-controlled invitation decisions, expiry boundary behavior, blocking, chat access rules, request redaction and clear preview limitations. Do not enable real payments. Do not misrepresent fictional profiles or sample evidence as verified real members/documents.

If production is requested, inventory missing backend schemas/functions, authentication, authorization, media services, moderation, deletion/export, abuse reporting, device telemetry, native capture, platform projects and signing. Ask the operator to connect services securely; never embed service-role credentials in a mobile/browser binary. Browser preview success does not establish native camera, network, payment, device or App Store readiness.

Use DEVELOPMENT_NOTES.md to review known boundaries. Test narrow viewports, text scaling, long copy, keyboard, invitation accept/decline/cancel/expire races, blocked conversations and sample-request behavior after every relevant change. Keep demo and production data separated; do not publish real profiles, private endpoints or account screenshots.
## AI host and model choice

Use a tool-capable AI host with repository/file access, a browser, connected email, and Apollo or Lusha. This repository does not install or authenticate those services automatically. ChatGPT Work/Codex and Claude environments differ; inspect the actual tools available before running.

Suggested starting point: GPT-6.1 Sol at Light/low or Medium effort for routine research and CRM work; GPT-6 Astra for difficult setup, reasoning and repairs. A newer capable model is fine if available. These are recommendations, not a benchmark or a promise of compatibility. Claude users can use a current tool-capable Claude model; OpenAI model names are not Claude options.

Model reference checked 2026-11-10: [OpenAI model guidance](https://learn.chatgpt.com/docs/models?surface=web). Recheck your model picker and tool access rather than hardcoding future model names. Model subscriptions, provider credits and cloud compute may cost money.
